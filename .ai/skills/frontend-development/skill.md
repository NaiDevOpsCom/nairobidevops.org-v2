# Frontend Development

## Tech Stack

- React 19.2.7 with TypeScript 6.0 (strict mode)
- Vite 8.1.3 for build
- Tailwind CSS 4.2.1 with PostCSS
- shadcn/ui (New York style) with Radix UI primitives
- Wouter 3.10.0 for hash-based routing
- TanStack React Query 5.101.2 for server state
- React Hook Form 7.80.0 + Zod 4.4.3 for forms
- Motion 12.42.2 for animations (formerly Framer Motion)

## Directory Structure

```
frontend/
├── client/src/
│   ├── components/       # Reusable UI components
│   │   └── ui/           # 51 shadcn/ui primitives
│   ├── pages/            # Page components (one per route)
│   ├── hooks/            # Custom React hooks
│   ├── contexts/         # React contexts (ThemeContext)
│   ├── lib/              # Utilities (cloudinary, youtube, constants)
│   ├── data/             # Static content (blog, events, FAQ data)
│   └── types/            # TypeScript type definitions
├── shared/               # Shared between client and scripts
│   └── routes.ts         # Route definitions
└── scripts/              # Build and utility scripts
```

## Component Patterns

- **Pages** go in `client/src/pages/` — one file per route, named after the page
- **UI primitives** go in `client/src/components/ui/` — generated by shadcn, do not edit directly unless necessary
- **Custom components** go in `client/src/components/` — like `Navbar.tsx`, `Footer.tsx`, `SEO.tsx`
- Path alias `@/` maps to `client/src/`

## Data Fetching

- Use TanStack React Query via `useJobs()` and `useLumaEvents()` hooks
- Define queries in `client/src/hooks/` using the shared `queryClient`
- API calls go through Vite dev proxy (`/endpoints` → PHP, `/api/luma` → Luma)
- Mutations use `useMutation` with cache invalidation

## Routing

- Wouter with hash-based routing
- Routes defined in `frontend/shared/routes.ts`
- Route-to-component mapping in `client/src/App.tsx`
- No React Router — do not import from `react-router-dom`

## Styling

- Tailwind CSS v4 with CSS variables for theming (dark/light mode)
- Custom NDC brand colors in `tailwind.config.ts`: `darkblue (#023047)`, `midnight (#001E2B)`
- Dark mode via `class` strategy — use `ThemeContext` to toggle

## Build

- `npm run dev` — local dev with HMR at localhost:5173
- `npm run build` — standard build
- `npm run build:prod` — hardened build (no sourcemaps, no console/debugger)
- Production uses `terser` minification; dev uses `esbuild`

## Testing

- Vitest with jsdom environment
- Test files co-located in `__tests__/` directories
- Run: `npm run test` or `npm run test:coverage`
